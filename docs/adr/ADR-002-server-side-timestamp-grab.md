# ADR-002: Server-side Timestamp for Grab Judgment

## Status
Accepted

## Context
2人のプレイヤーが同時に同じ札を取ろうとした場合、誰が先に取ったかを判定する仕組みが必要。

## Decision
サーバー側で取り札リクエストの到着順（先着順）で判定する。mutex によるロックで排他制御する。

## Rationale
- **公平性**: クライアント側のタイムスタンプは改ざん可能。サーバー到着順が最も公平。
- **シンプルさ**: mutex ロックにより「最初にロックを取得したプレイヤーが勝ち」という単純なモデル。
- **ネットワーク遅延**: クライアント間のネットワーク遅延差は不可避だが、一般的なWebアプリでは許容範囲（数十ms以内）。
- **代替案**: クライアントタイムスタンプ送信方式はチート可能、ランダム判定はゲーム性を損なう。

## Consequences
- ネットワーク遅延が大きい環境では不利になるプレイヤーが生じうる（将来的にリージョン別マッチングで緩和可能）
- サーバー側の処理が軽量で、スケーラビリティに影響しない
